Two main ideas about how this site should work

1. Every page - called a bubble - is about one thing.
2. Each bubble is also an object meaning it can be programmatically manipulated.

Conceptually, the first idea is fairly common amongst the wiki community. The second idea is something I became aware of through the [smallest federated wiki work](https://hapgood.us/2014/06/04/smallest-federated-wiki-as-an-alternate-vision-of-the-web/). However, it also echoes Alan Kay's ideas of the [[protean]] nature of digital technology and underpinned much of my practice (e.g. [[gather-weave-augment]]). 

Practically, the use and structure of the Markdown files that underpin each page on this site help with this. Perhaps largely to [Foam](https://foam.md) being yet another note-taking system using Markdown. Each bubble includes front matter (containing information about the bubble) and the markdown (the actual content of the bubble). Amongst the information about each bubble is `type` specifying the type of page.  Not a huge leap for `type` to be used to think about each bubble as an object of a particular "class". 

All this makes it possible to write code that can [[gather-weave-augment]] the data stored here. For example, the following table lists all the types on this site. It's generated by a [[computational-components]] (macro).

## Bubble design

A markdown file typically contains

- front-matter metadata - in YAML format;
    - `type` - defining the bubble type
    - `aka` - list of other related types/bubbles.

        Points to other types to which the object is also an example of. e.g. the observation of a plant would be `type: observation` but it may also be `aka-types: [ plant, single-plant, garys-ficus ]` i.e. an observation of both a species of plant and an individual plant. The list might also include the wikiLink for a specific bubble for that individual plant `garys-ficus`
    - other fields used as per needs for the specific bubble type
- content - in markdown format.

`corpus.py` creates Python dicts from a Markdown file with the following structure

```python
      {
        "content": "content of file",
        "yaml": { _all yaml defined variables_ },
        "filePath": "/path/to/file.md"
        "linkDefs": { 
           ...
        }
        ...
      }
```




## Bubble types

### In use bubble types

| Bubble type | Description |
|-------------|-------------|
| `note` | General note about some topic  |
| `index` | Landing page for a collection of related notes |
| `work-history` | Object definition for [[wood-duck-work-history]] component |
| `recipe` | Recipes used regularly - see [[recipes]] |
| `zone` | Defines one of the [[wood-duck-meadows]] zone |
| `computational-component` | A computational component - see [[computational-components]] |
| `colophon` | Notes about the site itself - see [[colophon]] |
| `quote` | A quote from some source - see [[quotes]] |
| `post` | A blog post |
| `plant` | Details about a species of plant found at [[wood-duck-meadows]] |
| `single-plant` | Details about an individual plant found at [[wood-duck-meadows]] |
| `graph-visualisation` | Bubble defining a graph visualisation - see [[graph|Bubble network visualisation]] |
| `mathContent` | A bubble containing mathematical content from my short stint as a wannabe mathematics teacher |
